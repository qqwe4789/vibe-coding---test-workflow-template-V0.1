# Rollback Runbook

## 1. 触发条件

满足以下任一条件可触发回滚：

- 生产故障导致核心路径不可用。
- 新版本造成明显性能退化或错误率上升。
- 数据一致性风险无法在短时间内修复。

## 2. 回滚路径

### 路径 A：代码回滚（默认）
1. 在对应合并 PR 页面执行 Revert，生成回滚 PR。
2. 补充回滚原因、影响范围、验证结果。
3. 走最小审批流程并合并。
4. 观察关键指标恢复情况。

### 路径 B：配置/功能降级（可选）
1. 关闭对应功能开关或回退配置。
2. 验证核心业务恢复。
3. 记录降级时间窗口和恢复计划。

## 3. 回滚验证清单

- 核心功能可用性恢复。
- 关键错误日志明显下降。
- 监控指标恢复到基线范围。
- 已通知相关团队和干系人。

## 4. 事后动作

- 24 小时内提交 RCA（根因分析）。
- 将预防措施写入模板、指令或自动化检查。
- 在每周复盘中跟踪改进项完成状态。
