# Workflow Metrics (DORA + Team)

## 1. 核心指标（首期）

- Lead Time for Changes：从 Issue 开始开发到 PR 合并的时长。
- Deployment Frequency：单位时间内成功发布次数。
- Change Failure Rate：引发故障或回滚的变更占比。
- MTTR：从故障发生到恢复服务的平均时长。

## 2. 补充指标（可选）

- PR 一次通过率。
- PR 平均评审时长。
- 需求兑现率（按 Sprint）。
- 回滚演练通过率。

## 3. 数据来源建议

- GitHub Issues/PR：周期、状态、关联关系。
- GitHub Actions：检查通过率与耗时。
- 监控平台：故障与恢复时间点。

## 4. 周期与治理

- 每周：团队复盘，观察趋势并记录阻塞。
- 每月：优化门禁与模板，评估是否增加自动化检查。
- 每季度：评估流程 ROI（速度、质量、稳定性）。

## 5. 指标使用原则

- 指标用于发现系统问题，不用于单点评价个人。
- 对异常值做上下文解释，避免机械比较。
- 指标改进必须配套具体行动项与责任人。
